# 无人值守夜跑的规矩

这份是给夜里替我干活的 agent 看的，也是早上我自己复核的清单。
核心前提：**这一夜没有任何真实环境验证** —— 红区只有人能进，而人在睡觉。
所以所有判据必须机器可判，所有"看起来对"一律不算数。

## 边界

- **做**：v1 = 目标 1（批量扫描）+ 目标 2（结果归档）。阶段 P1–P6，见 `PROJECT_BRIEF.md` §12。
- **不做**：目标 3（接 SNP_RLC_Extractor 做批量对比）是 v2。范围不许自己长出来。

## 一票否决

```
sh scripts/check.sh
```

退出码就是判据。**任何一项红 = 这个阶段没完成**，不许进下一阶段，不许"大体上通过"，
不许把失败的测试标成 skip 绕过去。

## 不许碰

| 路径 | 为什么 |
|---|---|
| `CLAUDE.md` 的硬约束段 | 那是项目宪法，不是可协商的实现细节 |
| `PROJECT_BRIEF.md` | 设计权威，只有人能改（而且它不进 git） |
| `tests/fixtures/production_cmd.local.json` | golden 期望值。改它 = 测试自己证明自己 |
| `tests/fixtures/production_cmd.sha256` | 上一条的锁 |
| `mockups/` | 界面草图是设计成果，产品代码另开 `gui/` |
| `references/` | 红区取回的证据，只读 |
| `.gitignore` 的红区段 | 唯一的泄漏防线 |

## 防自证三条

无人监督时最大的风险不是跑不完，是**写出自己证明自己的测试**：实现方生成 argv，
又由实现方决定期望的 argv 是什么，于是测试全绿而命令是错的。

这不是假想 —— MVP 里踩过一次：排除规则写 `--sparam` 前缀误伤了 `--sparamImpedance`，
两边同时被跳过，diff 空得非常好看，但根本没比。**空过的测试比没测更坏。**

1. **期望值只能来自人抽取的 fixture**，不许在测试里现算期望值。
2. **每条关键测试要有反向验证**：故意改一个值必须被抓到。没有反向验证的测试视为无效。
3. **每个阶段后由独立审查 agent 复核**，它不写代码，只回答：
   测试真的在测东西吗？有没有自证？`check.sh` 真绿了吗？范围有没有长出来？
   查出问题就打回重做，不许放行。

## git

- **允许 commit**（每个阶段一个，信息写清这阶段做了什么、check.sh 什么结果）。
- **禁止 push。** push 到 public 是外向不可逆动作，早上人看过再推。
- pre-commit 闸门必须保持启用，不许 `--no-verify`。

## 环境事实（别浪费时间去试）

- 本机没有 `ewave` / `dsub` / `strmout`，**不可能**真跑。别写依赖它们的验证步骤。
- 目标机登录 shell 是 csh/tcsh，Python 3.11.4，**无装包权限** → 只用 stdlib。
- GUI 用 tkinter，import 必须惰性（无 `$DISPLAY` 的 ssh 会话里 CLI 要能用）。
- 源码零站点标识符。坐标靠**运行时发现**（解析官方 run 目录）或 site-local 配置。

## 早上要交出来的东西

1. **红区验证包** —— 一条命令能拿去红区跑 dry-run，不用先读代码。
2. **交接报告** —— 每个阶段做了什么、`check.sh` 结果、**哪些地方我没把握**、
   红区第一次跑该看什么、失败了怎么办。
3. 完整的 `git log`，一阶段一个 commit，没有 push。

报告里"我没把握的地方"这一节**必须写实**。夜里没人拦着，写得漂亮没有意义，
写得准才有意义。
